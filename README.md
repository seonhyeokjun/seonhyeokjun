## 소개

반복되는 장애와 데이터 불일치의 원인을 찾아 구조를 개선하는 일을 해왔습니다. 올라핀테크에서는 선정산 회수·환급 배치를 Java로 단계적으로 옮겼고, 페이쿼리에서는 Classic ASP 결제 시스템을 중단 없이 Java로 전환한 뒤 회원·결제·정산을 세 서비스로 분리했습니다.

최근에는 AI를 코드 분석·설계·리뷰 흐름에 연결하고, 담당자가 바뀌어도 작업 배경과 판단이 남는 문서화 환경을 만들고 있습니다.

## 주요 경험

| 영역 | 작업과 결과 |
| --- | --- |
| 선정산 회수 정합성 | 은행 출금과 내부 원장·잔액 반영 구조 개선. 월 5~20건 발생하던 금액 불일치가 Java 전환 후 5개월간 0건 |
| 결제 시스템 전환 | 연 3,000억 원 규모 Classic ASP 결제 시스템을 서비스 중단 없이 Java로 전환하고 회원·결제·정산을 3개 서비스로 분리 |
| 조회 성능 개선 | 중첩 서브쿼리를 JOIN 중심으로 재설계하고 집계·변환을 애플리케이션으로 분리. 대표 결제 조회 최대 30초 → 0.1초 |
| AI 분석·문서화 | 24개 저장소의 분석·설계·구현·리뷰 흐름을 표준화하고 업무 배경과 히스토리를 위키 300건 이상으로 축적 |
